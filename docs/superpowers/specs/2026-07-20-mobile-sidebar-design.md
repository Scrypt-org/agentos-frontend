# INJ Pass 移动端侧边栏设计

日期：2026-07-20  
目标项目：`inj-pass-frontend`  
目标页面：`/`、`/welcome`、`/dashboard`

## 背景

三个目标页面共用 `InjPassChatShell`。其桌面侧边栏使用 `hidden ... lg:flex`，因此视口小于 Tailwind `lg` 断点时侧边栏被完全移除；移动端顶部目前只显示品牌名称，没有打开导航的按钮。结果是新聊天、搜索、钱包、DApp Market、Campaign、Skills、Space、Support 和账户菜单等入口在手机上无法访问。

主容器还使用 `h-screen`，部分浮层使用固定 `360px` 宽度。在带动态地址栏的移动浏览器中，这可能造成可视高度不准确或横向溢出。

## 目标

- 在手机和平板窄屏上提供可打开、可关闭、可滚动的侧边栏。
- 保留桌面端现有的展开和 76px 折叠行为。
- 复用现有侧边栏内容与事件处理，不改变钱包、聊天或 DApp 业务逻辑。
- 防止抽屉打开时背景误操作和页面滚动。
- 避免移动浏览器动态地址栏和固定宽度浮层造成基础布局问题。

## 非目标

- 本阶段不全面重排所有钱包卡片、弹窗、表格和 mini app 内容。
- 不改造 `/send`、`/swap`、`/settings` 等独立页面。
- 不引入新的 UI 组件库、路由系统或全局状态库。
- 不改变桌面端侧边栏的信息架构或视觉语言。

## 方案比较

### 方案 A：同一侧边栏响应式切换（采用）

保留当前侧边栏 JSX，在移动端将其变为固定定位的左侧抽屉，在桌面端恢复普通文档流。新增一个本地 `mobileSidebarOpen` 状态控制位移和遮罩。

优点是改动集中、内容不会出现两份、后续新增菜单项天然同时覆盖桌面与移动端。缺点是侧边栏 class 组合会稍复杂，需要明确区分移动抽屉状态与桌面折叠状态。

### 方案 B：复制一份移动端侧边栏

分别维护桌面和移动端 JSX。初次实现容易理解，但菜单内容、权限和事件会产生双份维护成本，也容易遗漏未来功能，因此不采用。

### 方案 C：将侧边栏完整拆分为新组件后再适配

组件边界最整洁，但当前 `InjPassChatShell` 中大量状态和回调直接服务侧边栏，拆分会扩大改造范围，不符合“最快让移动端可用”的目标。本阶段不采用；后续若继续全面响应式重构，可单独实施。

## 交互设计

- 小于 `lg` 时，顶部品牌左侧显示 44px 左右的菜单按钮。
- 点击按钮后，侧边栏从左侧滑入，宽度为 `min(86vw, 320px)`，高度覆盖当前动态视口。
- 抽屉后方显示半透明遮罩。点击遮罩、侧栏关闭按钮或按 `Escape` 均关闭抽屉。
- 抽屉打开时锁定 `body` 的纵向滚动；组件卸载或切换回桌面尺寸时恢复。
- 点击会切换主内容视图的侧栏入口后自动关闭抽屉。仅展开钱包、DApp Market、Campaign 等侧栏分组时不关闭。
- 移动端不展示桌面的 76px 折叠形态；侧栏头部按钮在移动端表达“关闭”，桌面端仍表达“折叠/展开”。
- 遮罩位于主内容之上、抽屉之下；抽屉层级应低于业务关键模态框，避免覆盖交易授权等对话框。

## 组件和状态

改动集中在 `app/components/InjPassChatShell.tsx`：

- 新增 `mobileSidebarOpen: boolean`。
- 新增打开、关闭辅助函数，供顶部按钮、遮罩和导航入口复用。
- 现有 `sidebarCollapsed` 继续只描述桌面折叠状态。
- 现有 `<aside>` 增加移动端固定定位、transform、宽度、阴影和层级 class；`lg` 以上覆盖回当前布局。
- 主内容顶部增加移动菜单按钮。
- 主容器高度由 `h-screen` 调整为 `h-dvh`，并保留兼容的最小高度策略（如实际构建环境需要）。
- 登录菜单等明显的固定宽度浮层改为 `w-[min(360px,calc(100vw-2rem))]`。

不使用根布局里遗留的 `.sidebar-container`。该容器没有实际侧栏内容，和 `InjPassChatShell` 的左侧导航不是同一实现；接入它会引入跨组件注入和双重遮罩问题。

## 可访问性与异常处理

- 菜单按钮提供 `aria-label`、`aria-expanded` 和 `aria-controls`。
- 移动侧栏使用稳定 `id`；关闭按钮提供明确的可访问名称。
- `Escape` 监听只在抽屉打开时生效，并在清理函数中移除。
- body 滚动锁在 effect 清理阶段恢复，避免热更新、路由切换或异常卸载后页面持续锁定。
- 遮罩使用按钮语义或带明确标签的可交互元素，支持键盘操作。
- 动画沿用现有 300ms 过渡，并尊重浏览器的 reduced-motion 行为。

## 测试与验证

### 自动测试

- 为移动侧栏的纯状态/样式决策抽取足够小的辅助逻辑时，为其添加单元测试。
- 运行现有 Vitest 测试，确保业务逻辑无回归。
- 运行 ESLint 与生产构建，检查 class、Hooks 和 TypeScript 错误。

### 浏览器验证

至少验证以下视口：

- 390×844：菜单按钮可见，抽屉可打开、滚动和关闭，主内容不可误触。
- 768×1024：仍使用移动抽屉，侧栏内容完整。
- 1024×768：切换到桌面侧栏，移动遮罩和按钮消失。
- 1440×900：桌面展开/折叠行为保持不变。

同时检查浅色和深色主题，以及侧栏中的新聊天、搜索、钱包/DApp 分组、Skills、Support、账户入口。

## 验收标准

- `/`、`/welcome`、`/dashboard` 在小于 `lg` 的视口中都有明显的侧栏入口。
- 移动抽屉可通过菜单按钮打开，并可通过关闭按钮、遮罩和 `Escape` 关闭。
- 抽屉内容可纵向滚动，所有原有侧栏入口可操作。
- 打开抽屉时背景不滚动、不接受指针操作。
- 从窄屏切换到桌面宽度后，不残留遮罩或 body 滚动锁。
- 桌面侧栏的 286px 展开、76px 折叠和现有功能没有回归。
- 390px 宽度下顶部和登录浮层不产生横向页面滚动。
